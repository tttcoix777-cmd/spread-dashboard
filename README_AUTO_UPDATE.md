# 日経225−NYダウ 毎日更新ガイド

## 現在の状態

自動取得・計算・保存・画面表示のプログラムと、毎日実行するGitHub Actionsを用意しました。TFX公式への実際の取得を確認し、12項目の検証に合格しています。GitHubリポジトリが未作成のため、定期実行とインターネット公開はまだ有効ではありません。ローカル画面に「確認済み」と出ることは、毎日の運転開始を意味しません。

銀−プラチナの価格ファイル・計算・画面は変更していません。この一式が自動更新するのは日経・ダウだけです。実注文を出す機能や口座接続はありません。

## 自動更新の仕組み

毎日10:30（日本時間）にGitHub側でプログラムを動かします。TFXの公式履歴ページに記載された商品名・商品コードを確認し、日付別CSVから2026年リセット商品の両脚の始値と終値を取得します。「清算値」は終値として使いません。

保存済み履歴に未取得日を追加します。同一日の同一価格は重複除外し、異なる価格なら停止します。欠損、日付の矛盾、不正な価格、OHLCの矛盾、前回終値に対して始値または終値が20%を超える変動も停止対象です。自動補完しません。20%は品質警告の基準であり、売買パラメータではありません。

SpreadはNYダウ終値−日経225終値。20MA・50MAは共通取引日の終値サヤの単純平均、10日変化は現在のサヤ−10共通取引日前のサヤです。Bは20MA<50MA、直前の連続拡大合計500ポイント以上、当日の縮小反転。C2はBかつ10日変化<0。既存固定条件・利確1000・損切り2000・最大30営業日・翌共通取引日始値の扱いを維持しています。仮想保有は2026-10-03から保有なしで開始します。

2027年商品も並行して取引されていますが、既存検証の2026年商品を維持します。公式商品名と取引期間を毎回照合し、日経2026の最終取引日2026-12-10を過ぎたら停止します。別年限への切替は新しい検証が必要です。設定だけを書き換えて継続しないでください。

参照元：[TFX公式履歴](https://www.tfx.co.jp/historical/cfd/) / [2026年商品の公式日程](https://www.clickkabu365.jp/newsfile/article/20250815-10)

## 初回設定と公開方法（GitHub Pages）

1. 配布ZIPを展開してください。中に `dist/`、`auto_update/`、`.github/workflows/update.yml` があります。これらがリポジトリの最上段に置かれる構成です。
2. GitHubにログインし、新しいリポジトリを作成します。無料でPagesを使う場合はPublicを選択します。Publicの場合、同梱の価格・更新ログ・ソースも公開されます。個人情報や実口座の取引履歴は入れないでください。
3. GitHub Desktopの「File → Add local repository」で展開先を選び、案内に従ってローカルリポジトリを作り、「Publish repository」で公開します。ブランチ名を `main` にしてください。すでにWeb側で作ったリポジトリを使うなら、それをCloneしたフォルダへ一式をコピーしてCommit・Pushします。隠しフォルダ `.github` も必ず含めます。ZIPファイルそのものをアップロードするだけでは動きません。
4. リポジトリの「Settings → Actions → General → Workflow permissions」で「Read and write permissions」を選んで保存します。組織の制限やmainの保護で書き込みが禁止されている場合は、その管理設定の対応が必要です。
5. 「Settings → Pages → Build and deployment → Source」を「GitHub Actions」にします。
6. 「Actions → TFX daily update and publish → Run workflow」でmainを指定して初回実行します。全体が緑になったことを確認します。
7. 「Settings → Pages」に表示される公開URLを開き、日経・ダウ欄の最終試行・正常更新日時を確認します。以降はmainに置かれたスケジュールで毎日実行します。

GitHubの実行には遅延があり、10:30ぴったりは保証されません。長期間活動のない公開リポジトリでは定期実行が停止されることがあるので、Actionsの状態を確認してください。定期実行を無効にしないでください。

公開は成功時だけでなくデータ取得エラー時も行います。古い正常価格を保持したまま、エラーJSONを公開し、画面に警告を出します。再公開そのものが失敗した場合は、画面が最後の更新確認から36時間後に警告します。即時検知ではないため、Actionsの失敗通知も有効にしておくと確認しやすくなります。

Netlify/Cloudflare Pagesを使う場合は、同じリポジトリを接続して公開ディレクトリを `dist` に設定できます。ただし同梱workflowのGitHub Pages公開手順を、そのサービスに合わせて変更する必要があります。この配布物では外部サービスとの接続は未設定です。

## 毎日の動作

公式取得 → 検証 → B/C2計算 → CSV/JSON保存 → ログ保存 → mainへ保存 → GitHub Pagesへ公開、の順に進みます。土日・休場日で新しい取引日がなければ、価格を作らず「新しい取引日なし」と表示します。公式最新日が4暦日以上前なら、長期休場や公表遅延の確認を促して停止します。

ブラウザは5分ごと、また画面へ戻ったときに公開JSONを確認します。再読み込みボタンでも確認できます。ページの表示だけではTFXの取得は実行されません。GitHub側の処理が必要です。

NO SIGNALは候補なし、B SIGNALはBのみ、B + C2 SIGNALは両方成立です。C2 SIGNAL単独は論理上成立しません。C2欄にもBの全条件を満たすことを表示します。仮想保有と実際の保有は別です。実建値は画面で手入力でき、外部へ保存しません。

## エラー確認方法

画面にDATA UPDATE ERROR、最終正常更新日時、正常価格日、理由を表示します。下の価格や決済幅は過去の参考値になり、現在のエントリー候補を停止します。

GitHubのActionsで赤い実行を開いて該当ステップを確認します。`auto_update/data/status.json` に理由、`auto_update/logs/YYYY-MM.csv` にdate/dow/nikkei/spread/ma20/ma50/spread_10d_change/signal_b/signal_c2/update_status、時刻と理由を保存します。各実行のJSONと取得原本CSVもlogsに保存します。エラー行の価格は最終正常値であり、その日の新しい取得値ではありません。

TFXのサイト構造や価格の訂正が変わった場合は、原本と履歴を照合して原因を解決してください。警告を消すための価格補完・閾値変更・パラメータ変更はしないでください。GitHub公開失敗やmainへの保存失敗の場合はActionsログを確認してください。

## 手動更新方法

GitHubのActionsから「Run workflow」を実行するのが簡単です。

PCで動かす場合はPython 3.11以上を用意し、展開したフォルダで次を実行します。外部ライブラリの追加は不要です。

```powershell
python auto_update/update_dow_nikkei.py --site-dir dist
python -m unittest discover -s auto_update/tests -v
```

更新したdata/logsとdistのCSV/JSONをGitHubへCommit・Pushし、Run workflowで再公開してください。処理が途中で止まって `auto_update/data/.update.lock` が残った場合は、他の更新処理が動いていないことを確認してからロックを取り除きます。

画面のCSV読み込みはその画面だけの手動確認です。自動公開データは変更しません。`date,ny_dow_open,ny_dow_close,nikkei225_open,nikkei225_close` を推奨します。「自動データに戻す」で公開された正常データまたはエラー状態に戻ります。

## ファイルの配置

`dist/` が公開画面です。`auto_update/update_dow_nikkei.py` が取得・検証・保存、`signal_engine.py` が固定判定、`data/` が履歴と生成結果、`logs/` が監査記録、`tests/` が固定原本を使った検証です。`frozen_settings.json` は既存条件の記録です。requirements.txtは外部依存がないことを示します。`.github/workflows/update.yml` が毎日実行と公開を担当します。
