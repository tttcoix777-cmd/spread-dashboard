デフォルトはV3と同じ2026年リセット銘柄（G26/JPY、V26/JPY、P26/JPY）。Viewerは年限を分離し、過去年限への選択変更を明示的に行います。既存V3の保存履歴には2025年1月からの値がありますが、ViewerはTFX原本に対象年限が存在する期間だけを採用します。既存V3履歴は変更していません。

取引単位は3銘柄とも価格×100円/枚です。[公式商品仕様](https://www.clickkabu365.jp/start/publication/pdf/clickkabu365_pamph_notonbo.pdf) を参照し、β = B枚数×B乗数 ÷ (A枚数×A乗数) と説明しています。表示価格は円価格ポイントです。枚数比を取引単位から一意には決められないため、任意の固定βを初期設定していません。V3の3×銀−Ptとは計算表示を分けています。

## 同期・欠損・計算

同じTFX帳票日と同じ年限の値だけを組み合わせます。終値欠損はnullに保ち、補間・前日値の持越し・清算値による補完はしません。日足は欠損箇所で線を切断します。週足は月曜始まり、月足は暦月の最終帳票日を使い、両脚の日付を個別にずらしません。最終帳票日の片脚が欠損した足は指標を算出しません。週・月の最後には進行中の足を含みます。

各時間足への集約後、表示範囲で切り出す前に20足の平均・標準偏差を計算します。現在までの値だけを使い、未来参照はありません。欠損後は20連続有効足を必要とします。SD=0または20足未満のZは「—」です。

帳票ヘッダー・日付・件数・商品コードと名称・OHLC・正数・呼値（金/Pt:1、銀:0.1）を検証します。同一年限・同一銘柄の50%超の価格変動は単位/原本確認のため停止します。これはViewerの品質チェックで、売買条件には影響しません。最新帳票のSHA256が保存済みと違う場合も手動照合を要求します。

## 自動更新

既存.github/workflows/update.ymlにViewer専用ステップを追加しました。毎日10:30 JST頃の既存スケジュールで、V3・C2の取得後にupdate_viewer.pyを実行します。公式ページに掲載された未収録日を差分取得し、最新日は再検証します。取得失敗時は以前の正常な価格JSONを保持し、Viewer状態JSONに失敗理由と最終成功時刻を保存して公開します。Viewerの失敗が既存2処理を止めないよう、独立ステップとcontinue-on-errorを使用しています。

ブラウザは新タブ初回表示・5分ごと・再読込ボタンで公開JSONを取得します。価格日から4暦日超で保存済み過去値の警告を表示します。ページを開くだけではTFX取得は実行されません。
